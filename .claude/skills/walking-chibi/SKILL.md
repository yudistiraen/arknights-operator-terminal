# Walking Chibi — render & framing standard

A walking mascot (`WalkingChibi.tsx`) stacks two videos, idle (`chibiSrc`) and walk
(`chibiMoveSrc`), and applies **one** `chibiFraming` transform to both. That puts two hard
requirements on every walkable skin:

1. **Idle and move share one camera** — same scale and ground line *inside* the video.
   Otherwise the mascot visibly shrinks/grows or sinks/floats the instant it stops walking, and no
   `chibiFraming` value can fix it (the transform is shared). Blue Poison, Reed, Mountain and 58
   other pairs shipped broken this way before this standard existed.
2. **`chibiFraming` follows the Amiya standard** — so every mascot appears at the same on-screen
   height, feet line and center as Amiya base (the reference the user approved).

Detailed background: `scripts/chibi-pipeline/README.md` ("Walking chibi: idle + move MUST share
one camera", "Walking chibi framing standard") and `operator_context.md` (standar walking chibi).

## The standard

| Rule | Value |
|---|---|
| Source | `fexli/ArknightsResource` dorm model (`spine/<char>/build_<char>[_skin]/Spine`), local clone first. Never wiki.gg. |
| Clips | idle = `Relax` (fall back to another clip only if `Relax` is missing / 0-duration), move = `Move` |
| Camera | ONE shared camera for idle + move (`render-walking-pair.mjs`) — default 600×600, 30 fps, 60 samples, 12% margin |
| Files | `public/operators/<slug>/chibi[-skinN].webm` + `chibi-move[-skinN].webm` (alters: `<slug>/<alter-slug>/…`) |
| On-screen size | Move-clip body height = **1.0125×** sprite box (ears/horns included) |
| Feet line | **1.0475×** box height |
| Horizontal center | **0.5187×** box width |
| Max width | **1.5×** box (wide non-humanoid cap) |
| `chibiFraming` | generated by `standardize-walking-framing.mjs`, never identity, never hand-tuned |
| `chibiDetailFraming` | operator-page HUD box only; leave alone (script pins the old value when needed) |

## Workflow — new operator or skin

### 1. Find the char id and the dorm folder for each skin

- Char id from `.firecrawl/character_table.json` by English `name` (e.g. Blue Poison =
  `char_129_bluep`). Names with apostrophes (Ch'en, Kal'tsit) and very new operators missing from
  that table: list `ArknightsResource/spine/` and pick by eye.
- **Never map skins to folders by name or listing order** — suffixes (`marthe_3`, `boc_6`,
  `witch_1`) carry no skin-order meaning, and guessing has been wrong repeatedly. Decide visually:

```sh
node .claude/skills/walking-chibi/probe-skin-folders.mjs <char_id>
```

  This renders a few low-fps `Relax` frames per folder into
  `scripts/chibi-pipeline/out/probes/<char_id>__<folder>/frames/`. Look at `frame_000.png` of each
  and compare against the skin art (`public/operators/<slug>/skinN.png`). When an older chibi of the
  skin already exists (re-render case), rank automatically:

```sh
.venv-audit/Scripts/python .claude/skills/walking-chibi/match-skin-folder.py <char_id> public/operators/<slug>/chibi-skin1.webm
```

  A correct match scores ~0.9–1.0 with a clear gap to the runner-up; the script warns if the top two
  are within 0.1 — then check the frames visually.

### 2. Render idle + move as a pair (shared camera)

```sh
MSYS_NO_PATHCONV=1 node scripts/chibi-pipeline/render-walking-pair.mjs \
  --model spine/<char_id>/build_<char_id>[_skin]/Spine \
  --idle-out scripts/chibi-pipeline/out/<slug>/chibi[-skinN].webm \
  --move-out scripts/chibi-pipeline/out/<slug>/chibi-move[-skinN].webm \
  --work-dir scripts/chibi-pipeline/out/<slug>/work-<folder>
```

- It must end with `Shared camera OK`. Never render idle and move with two separate
  `render-chibi.mjs` calls.
- Always pass a distinct `--work-dir` per folder (base and skins otherwise collide on model files).
- Extra options pass straight through, only when the symptom appears:
  - `--hide-slots "C_*"` — floating dorm props baked into the setup pose (e.g. Młynar W Dali's sword).
  - `--bounds-mode pixel-probe` — every sampled pose reports an identical, oversized bbox
    (invisible attachment fooling `getBounds()`); character renders as a tiny blob.
  - `--sample-mode t0` — fast-swinging dangling prop (chains, tails) causing a jump on loop.
  - `--idle-anim <clip>` — `Relax` missing or 0-duration (e.g. Togawa Sakiko).
- Look at one frame of each output before placing it (feet visible, nothing clipped, right skin).

### 3. Place files and wire the data

- Copy both `.webm` into `public/operators/<slug>/…` (output never goes straight into `public/`).
- In `src/data/operators/<slug>.ts`, on the skin entry, keep the field order the scripts parse:
  `chibiSrc: '…', chibiMoveSrc: '…', chibiFraming: { scale: 1, offsetXPercent: 0, offsetYPercent: 0 }`
  (identity is only a placeholder for step 4). `base` and `e2` usually share the same files.
- Any skin with both `chibiMoveSrc` and `chibiFraming` automatically joins the walking pool and gets
  the toggle — no component changes.

### 4. Apply the size standard

```sh
node scripts/chibi-pipeline/standardize-walking-framing.mjs --only <slug>          # dry run
node scripts/chibi-pipeline/standardize-walking-framing.mjs --only <slug> --write
```

Read the warnings:
- `move/idle height` > 15% — usually a pose difference (sitting idle). If the pair came from step 2
  it is NOT a camera problem; confirm visually and move on.
- `scale outlier` — check visually (big effects like Ch'en Holungday skin2's splash legitimately
  give scale ~3.8).

### 5. Verify

1. Audit the pair (head template matching, pose-independent):
   ```sh
   .venv-audit/Scripts/python scripts/chibi-pipeline/audit-walking-pairs.py <slug>
   ```
   Pass = ratio 0.96–1.04 and feet delta ≤ 2%. A `low-confidence` note alone is fine — it means
   the idle pose differs a lot from the walk, not that the camera does.
2. Look at it: one idle + one walk frame with the new framing next to Amiya — same height, same
   ground line. Then check in the running app (select the mascot via its walking toggle).
3. `pnpm exec tsc --noEmit -p .`

## Auditing everything (user asks to verify/rapihkan all walking chibi)

```sh
.venv-audit/Scripts/python scripts/chibi-pipeline/audit-walking-pairs.py > audit.jsonl
```

For each pair whose `problems` contain more than `low-confidence`: map it to its folder (step 1,
`match-skin-folder.py` against the current public idle), re-render with step 2, replace the files,
re-run step 4 for the touched operators, and re-audit.

Known pose-only flags (already verified as one shared camera — don't re-render):
Amiya skin2 (scooter), Amiya Medic base, Dusk skin2, Eyjafjalla skin2 (umbrella), Manticore skin2
(tail), Phantom skin1, Shining skin1 (sits).

## Setup — audit/match venv (one time)

numpy + OpenCV are not project dependencies; keep them in the gitignored `.venv-audit/`:

```sh
python -m venv .venv-audit
.venv-audit/Scripts/python -m pip install numpy opencv-python-headless
```

## Don'ts

- Don't leave `chibiFraming` at identity, and don't hand-tune or eyeball it — fix the video instead.
- Don't render idle and move separately, or pair a re-rendered move with an old idle (or vice versa).
- Don't trust skin folder names or listing order.
- Don't use wiki.gg chibi for walkable skins.
- Don't change `TARGET`/`REFERENCE` in `standardize-walking-framing.mjs` unless the user picks a new
  reference — then `--calibrate`, paste into `TARGET`, `--write` everything.
- Don't touch `chibiDetailFraming` to fix the walking mascot — it's only the operator-page HUD box.
- Shell gotchas: `node -e` with `>` or `=>` inside Git Bash leaves 0-byte junk files in the repo
  root — write a script file instead and delete any junk you created. Set `MSYS_NO_PATHCONV=1` when
  passing `spine/...` paths.
